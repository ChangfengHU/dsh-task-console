# Studio media recovery and source requirements

Future studio-bounded-v1 runs that stop with known pending media first consume one normal failed attempt. A durable marker permits bounded host status polling only after confirmed session disposal. The marker is tied to the original run and exact block event; leases, intervening actions, archived batches, unknown/no-ID submissions and exhausted retries prevent automatic resumption. The host polls at most two known jobs for one card per tick, no sooner than30seconds, with a90second lease and12 persisted attempts. Source calls never generate content or refund reservations. Image/voice ownership comes from ledger kind; parallel specialists do not wait for each other's unrelated jobs. Render recovery remains conservative.

An older blocked run does not acquire this marker retroactively. Console operators may call `reconcileStudioKnownOperation` with taskId, batchId, cardId, expectedRunId, intent, requestId and reason. It reads the original persisted job through the configured provider, records an operator intervention, and updates only the exact matching pending receipt using CAS. No caller-supplied result or URL is accepted; the response contains state only. It neither unblocks nor changes generation spend. Explicit `unblockCard` remains a separate audited action. A recovered historical trial is assisted, not an autonomous success. This endpoint is not an Agent tool.

Sound receipt v3 binds BGM/SFX IDs to the hash-verified original registered storyboard of the same batch/round. Removing a required cue fails even if the remaining files decode. Missing requirement metadata is explicitly unverified; intentionally empty arrays allow a film without music/effects. Legacy v2 replay keeps its original algorithm and carries no original-demand proof. Receipt coverage is not listening, licensing or artistic approval.

Package compatibility declares persisted sound-v3 and automatic-reconciliation support. Downgrade checks examine actual saved receipts/markers, including completed historical records; old runtime versions must not silently lose these contracts.

Validation includes actual SQLite scheduling, SDK progress boundaries, terminal/CAS races, restart, failed network, missing-job IDs, retry/lease limits, original sound hashes and legacy replay. First operator-helper test fixture used an event without the real kernel transition and failed; the fixture now executes the actual transition and all8 cases pass. No production autonomy or quality acceptance follows from these tests.
