# R2 配置资产迁移

在源 DSH 的任务看板 → 配置资产迁移，点「导出到 R2，生成迁移链接」。复制完整链接，在已部署同版本插件的目标机器粘贴，校验预览后确认导入。无需手工传文件。保留本地明文备份作为离线选项。

R2 仅存 AES-256-GCM 加密包。解密密钥在链接 fragment（`#key=`），下载请求不把它发送给 R2。完整链接是迁移凭证，持有者可以解密，请勿公开分享；只有 R2 对象地址无法解密。旧明文配置包仍可导入。

迁移范围：Task 定义、触发规则、角色与设计合同；Agent 定义、模型/权限/原生工具、MCP 工具和参数策略；两类 Actions；Agent 实际引用的 Skill 完整文件、脚本、资源和可执行权限；MCP/模型宿主配置、Task 插件策略、Studio 宿主配置和版本依赖清单。相同文件与 Skill 树只存一次，不同 Agent 的不同版本不合并。未知配置拒绝导出，不静默删除工具或权限。

不包含执行历史、会话、日志、产物、登录态、OAuth 或密钥值。密钥和可能含凭据的 args/env/headers 保留为空值及宿主绑定引用，目标机器需重新绑定。独立路径映射仅修改 Task cwd；插件路径、CLI 参数、外部工作目录与宿主资源需检查适配。

默认保留目标已有资产，新增 Task 停用，新增 MCP/模型配置停用；同 ID Agent 只有明确选择覆盖才备份后替换。插件/Studio 策略保存在私有迁移恢复清单，不插入第二份运行服务或自动替换目标全局配置。未受支持的手写 Cordis 组合和第三方插件二进制不在自动恢复范围。导入配置不等于运行验收通过，须验证模型认证、MCP/Skill 实际调用与业务工具后再启用任务。

旧 Fleet 引导安装器不能解密新链接：先正常部署 DSH 和相同插件，再在迁移页面导入，不向旧安装器发送解密密钥。

发布必须基于线上实际启用的 Studio 整合源码，不能覆盖成标准版。版本化预备目录、保留宿主配置、校验源/产物哈希、确认原生会话及 SQLite 执行声明均无 running 后才切换；不取消任务或顺便启用其他待发布功能。
